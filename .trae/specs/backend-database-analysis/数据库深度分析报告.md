### 1.1 数据库类型与配置

- **生产环境**: MySQL
- **双数据库支持**: 系统通过 `DB_TYPE` 环境变量动态切换 SQLite/MySQL

### 2.4 用户业务逻辑流程

#### 2.4.1 微信登录流程
```
POST /api/users/wechat-login
├── 接收 openid
├── findOrCreateUser(openid)
│   ├── 查询 users WHERE phone=? OR openid=?
│   ├── 用户存在 → 返回用户
│   └── 用户不存在 → 创建新用户（phone为空字符串）
├── generateToken({userId, openid, phone})
└── 返回 token + userInfo
```

#### 2.4.2 手机号验证码登录流程
```
POST /api/users/phone-login
├── 接收 phone, code, role
├── 验证验证码
│   ├── 查询 verificationCodes.get(phone)
│   ├── 校验 code 是否匹配
│   └── 校验是否过期（5分钟）
├── findOrCreateUser({phone, role})
├── generateToken()
└── 返回 token + userInfo
```

#### 2.4.3 实名认证流程
```
POST /api/users/real-name/verify
├── 接收 name, idcard, idcard_front, idcard_back
├── 验证身份证格式（正则校验）
├── 开发环境 → 直接认证成功
├── 生产环境 → 调用第三方实名认证接口
├── 更新用户信息
│   └── UPDATE users SET name, idcard, idcard_front,
│       idcard_back, real_name_status, real_name_at
└── 返回更新后的用户信息
```

### 3.5 支付方式与押金计算

#### 3.5.1 支付方式定义

| 值 | 枚举名 | 说明 |
|----|--------|------|
| 1 | PAY_ONE_MONTH | 押一付一（月付） |
| 2 | PAY_THREE_MONTHS | 押一付三（季付） |
| 3 | PAY_SIX_MONTHS | 押一付六（半年付） |
| 4 | PAY_YEARLY | 年付 |

#### 3.5.2 押金计算

- **默认押金** = 月租金（deposit = monthly_rent）
- 押金可通过 `deposit` 参数自定义

#### 3.5.3 合同总金额计算

```typescript
const calculateTotalAmount = (monthlyRent: number, paymentMethod: PaymentMethod, months: number): number => {
  const deposits = 1;  // 押金月数固定为1
  const paymentMonths = paymentMethod === PaymentMethod.PAY_ONE_MONTH ? 1 :
                         paymentMethod === PaymentMethod.PAY_THREE_MONTHS ? 3 :
                         paymentMethod === PaymentMethod.PAY_SIX_MONTHS ? 6 : 12;
  const totalRent = monthlyRent * months;
  const deposit = monthlyRent * deposits;
  return totalRent + deposit;
};
```

## 八、发现的问题与建议

### 8.1 数据结构问题

1. **物品清单字段冗余**
   - 问题：contracts 表已有 24 项物品清单字段，又创建了 contract_inventory 表但未使用
   - 建议：删除未使用的 contract_inventory 表，或统一使用该表

2. **签名数据冗余**
   - 问题：contracts 表已有 lessor_signature 和 lessee_signature 字段，又创建了 signatures 表但未使用
   - 建议：删除未使用的 signatures 表，或统一使用该表

3. **签署邀请数据冗余**
   - 问题：contracts 表已有 invite_code 和 invite_expires_at 字段，又创建了 sign_invitations 表但未使用
   - 建议：删除未使用的 sign_invitations 表，或统一使用该表

### 8.2 业务逻辑问题

1. **缺少 contract_items 表的使用**
   - 问题：文档中提到 contract_items 表用于存储合同条款，但代码中未实现
   - 建议：根据业务需求决定是否实现

### 8.3 安全建议

1. **验证码存储**
   - 当前：内存 Map 存储（verificationCodes）
   - 问题：重启服务后验证码丢失，且无法跨实例共享
   - 建议：使用 Redis 存储

2. **签名图片存储**
   - 当前：Base64 直接存储在数据库
   - 问题：数据库体积快速膨胀
   - 建议：存储到文件服务器，数据库只存路径
